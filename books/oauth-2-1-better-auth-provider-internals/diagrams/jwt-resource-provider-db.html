Provider + database

発行policyはAS DB、検証policyはRSにある

JWTでもAuthorization ServerとResource Serverの責務は統合しない。

AUTH DB

resource + JWKS

  • identifier / allowed scopes
  • signing algorithm / key id
  • client-resource link

BETTER AUTH

JWTを発行

  • reserved claimsを所有
  • audienceを固定
  • private keyで署名

RESOURCE API

local verify

  • JWKS public key
  • iss / aud / exp
  • route scope
trade-off：ASへの毎回のintrospectionは不要　／　revocationはJWTのexpまで遅れる場合がある
